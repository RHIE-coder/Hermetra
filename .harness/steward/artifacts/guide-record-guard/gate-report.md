## 1. 가이드 기록 누락을 검사가 잡는다

문제: 가이드를 고칠 때 옛 원문을 `past-guides.ts` 에 안 옮기면, 앱은 디스크의 낡은 사본을
자기 것으로 못 알아보고 그대로 둔다 — 사용자 파일이 없는 기능을 계속 가르친다. 2026-08-18 에
실제로 일어난 그 일이다. 앞 회차 기록에 "강제하는 검사는 없다"고 적혀 있었다.

`.claude/checks/check-seeded-docs.mjs` 신설. 작업 트리와 **HEAD** 를 견준다:

| 조건 | 판정 |
|---|---|
| 실리는 글이 지난 커밋과 달라졌는데, 그 지난 글이 기록에 없다 | FAIL |
| 지금 실리는 글이 기록에 들어 있다 | FAIL (목록마다 덮어써서 사람의 수정이 한 번밖에 못 산다) |
| 상수가 HEAD 에 아예 없다(이번에 새로 생김) | 통과 — 물러난 판이 아직 없다 |

설정으로 움직인다(`harness.config.json` → `checks.seeded-docs`: `source`·`record`·`docs[]`),
`npm run sweep` 에 `docs` 로 등록했고 `npm run sweep:docs` 로 따로 돌릴 수 있다.

**검사가 무는지 확인했다** — 장식이 아니라는 증거:

| 해 본 것 | 결과 |
|---|---|
| 기록 없이 `SEED_GUIDE_KO` 한 줄 고침 | FAIL, 문구가 "옛 원문을 그대로 옮겨 적어라"까지 말함 |
| 지금 판을 기록에 넣음 | FAIL, "기록은 물러난 판만" |
| 되돌림 | OK (문서 2건, 물러난 판 2건) |

구현 중 한 번 틀렸다 — 첫 스캐너가 **주석 안의 백틱**까지 리터럴로 세어 짝이 어긋났고,
`SEED_GUIDE_EN` 을 못 찾았다. 언어가 읽는 방식대로(줄 주석·블록 주석·따옴표 문자열을 건너뛰는
상태 기계) 다시 썼다. 이 파일들은 문서 주석이 코드를 백틱으로 인용하는 곳이라, 백틱만 세는
방식은 여기서 반드시 깨진다.

## 2. 확인용 스크립트가 실제 프로파일을 못 쓰게 한다

문제: 그 낡은 사본이 유저 워크스페이스에 놓인 경로 자체가, 내가 짠 확인용 스크립트가
`--user-data-dir` 에 그 사람의 진짜 프로파일을 넘긴 것이었다. `ui-shot.mjs` ·
`surface-verify.mjs` 는 임시 프로파일이 기본값인데, 손으로 짠 스크립트가 그 관례를 비껴갔다.

immunity ledger 항목 `real-profile-in-verification-script` 추가. `rule:` 정규식이 붙어 있어
**PreToolUse 훅이 그런 내용을 쓰는 것 자체를 막는다.**

| 해 본 것 | 결과 |
|---|---|
| 실제 프로파일로 launch 하는 내용 Write | 종료코드 2 — 차단, 항목 id 와 함께 |
| `mkdtempSync` 로 만든 임시 폴더로 launch | 종료코드 0 — 통과 |

훅은 `.claude/**` 와 마크다운을 안 본다(규칙을 설명하는 글이 자기 규칙에 걸리면 안 되므로).
그래서 이 보고서와 ledger 자신은 걸리지 않는다.

## 관찰 (차단 아님)

- 이 검사는 **커밋 경계에서만** 문다. 한 커밋 안에서 가이드를 고쳤다 되돌리면 볼 것이 없다.
  그것으로 충분하다 — 사용자에게 닿는 것은 커밋된 판이다.
- 규칙 정규식은 `--user-data-dir=` 뒤에 실제 프로파일 경로가 **글자로** 올 때를 잡는다.
  경로를 변수로 조립해 넘기면 못 잡는다. 정규식으로 갈 수 있는 데까지가 여기다.
