  기능을 여기에도 똑같이 적용한다.

### 무엇이 열렸나

담는 그릇이 하나에서 셋으로 겹쳤다: **흐름**(화면 여럿) ⊃ **묶음**(메시지 하나) ⊃
**표시**(자국 하나). 묶음과 화면은 서로 가로지른다.

- **묶음** — 메모창이 열려 있는 동안 그린 자국이 그 메모에 붙는다(모드 전환 버튼 없음).
  묶음 안 표시는 전부 같은 번호 배지를 달고, 어느 것을 눌러도 같은 메모가 열린다. 가리킨
  요소는 묶음이 아니라 **표시마다** 잡는다 — 묶음 전체를 감싼 사각형으로 재면 핀을 도입하며
  없앤 "거대한 상위 감싸개" 실패가 되살아난다. 지우개·되돌리기가 자국 하나 단위가 됐다.
- **흐름** — "다음 화면"이 지금 화면을 그림으로 굳히고 오버레이를 접는다. 접힌 동안 앱을
  쓰고 손잡이를 다시 열면 다음 단계다. 표시는 화면의 **신원**을 붙잡아(차례가 아니라) 순서를
  바꿔도 안 고친다. 지금 화면의 표시만 그리고 만진다.
- **초안** — 화면을 굳힐 때마다 `_draft-*` 폴더에 바로 쓴다. 보내기는 그 폴더를 최종 이름으로
  바꾸고 그림을 흐름 순서로 다시 짓는다(`screen-N.png` → `shot-N.png`). 닫기는 지운다.
  좌표·메모는 `sessionStorage` 로도 이어 붙어 새로고침을 넘긴다.

### 이식하며 바꾼 것

1. **HTTP 라우트 하나(`action` 분기) → 타입 붙은 채널 셋** (`dev:feedback:step` ·
   `:save` · `:discard`). 이 프로젝트의 IPC 계약이 채널당 입출력을 고정하므로, 한 채널에
   세 가지 뜻을 담으면 계약이 `unknown` 으로 흐려진다.
2. **화면 그림이 IPC를 건너지 않는다.** 캡처가 메인 몫이라(`webContents.capturePage()`)
   `step` 이 직접 찍어 초안에 쓴다 — 렌더러는 장당 2~3MB 를 들 일이 없고, 원본이 곁가지
   이득으로 적어 둔 것이 여기서는 구조상 기본값이다.
3. **테마를 화면마다 적는다.** 흐름 도중 테마를 바꿀 수 있어 피드백이 아니라 화면에 붙였다.
4. **옛 본문 호환 분기를 안 가져왔다.** 이 앱에서는 렌더러와 메인이 같은 빌드로만 만나므로
   죽은 길이다(CLAUDE.md §6 "죽은 코드 삭제").

### 이식 중에 잡은 버그 (원본에도 있다)

`badgeHit` 의 화면 필터가 표시의 `step` 을 읽는데, 그리는 중인 표시가 드는 필드는 `screen`
이다. **선택 필드라 타입은 통과하고** 런타임에는 늘 `undefined` 라, 화면 인자를 주면 어떤
배지도 안 잡힌다 — 즉 흐름 도입 이후 **배지를 눌러 메모를 다시 여는 길이 죽어 있었다.**
`screen`/`onScreen` 으로 맞추고 회귀 테스트(CASE-tools-019)를 걸었다. 이식 대상인 Rhaumos
쪽도 같은 상태다.

### 눈으로 확인한 것 (실제 앱, 화면 두 장짜리 흐름)

개발 모드로 강제 빌드(검증 후 되돌림)한 뒤 Playwright 로 실제 Electron 창을 몰았다.

1. `/bridge/scenarios` 에서 사이드바 `공유 버스` 를 탭(핀) → 메모 입력 → **메모창이 열린 채**
   화살표를 그림. 배지가 `①①` 로 둘 다 같은 번호.
2. "다음 화면" → `.harness/feedback/_draft-20260810-110928-bridge-scenarios/screen-1.png`
   가 생기고 오버레이가 접힘. 손잡이 옆 진행 표시 `화면 1 · 표시 1`.
3. 접힌 채로 사이드바를 눌러 `/bridge/bus` 로 이동 → 손잡이를 다시 염.
   **지난 화면 자국 0개** (좌표가 새지 않는다).
4. 목록에서 ① 을 다시 열고(메모 `여기서 공유 버스로 넘어가면` 이 그대로 들어 있음) 이어 찍음
   → 배지 `①`, 따로 하나 더 남겨 `②`.
5. 흐름 모달: `1단계 /bridge/scenarios 표시 ①` · `2단계 /bridge/bus 지금 화면 · 표시 ① ②`.
6. 보내기 → `20260810-110928-bridge-scenarios/` 에 `note.md` · `note.json` ·
   `shot-1.png` · `shot-2.png`. 초안 폴더는 사라짐, `screen-*` 안 남음.
   `note.md` 는 흐름 절이 맨 앞이고, ① 아래 "표시 3개가 한 요청 · 화면 2개에 걸쳐 있다"
   와 표시별 `[N단계 /경로]` · 각자의 요소(`nav-bridge-bus` / `Badge` / `CardContent`).
   두 그림 모두 그 화면의 표시만 있고 도구막대는 없다. 렌더러 콘솔 에러 0건.

확인에 쓴 폴더는 지웠다. 요소 사슬 꼬리에 붙던 react-router 내부 이름 `Navigation` 을
잡음 목록에 더했다.

### 회차 1 뒤에 고친 것 — 목록으로 다시 연 묶음의 안내

검증 중에 걸렸다: 다른 화면에서 묶음을 목록으로 다시 열면 **메모창이 안 뜬다**(그 묶음의
표시가 여기 아직 없어 붙을 자리가 없다). 기능은 되지만 화면에 아무 반응이 없어, 목록을 눌러도
안 눌린 것처럼 보인다 — **화면을 걸쳐 한 메시지를 남기는 유일한 길을 유저가 포기하게 되는
자리라** 그냥 두지 않았다.
