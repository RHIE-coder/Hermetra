## 1. "코드를 작성하는 화면 영역이 좁다"

**제보** — `.harness/feedback/20260814-173557-studio-browser`. "전체적인 레이아웃은 마음에
들다만 코드를 읽고 편집하기가 너무 힘드네. 그리고 GUIDE.md도 화면이 좁아서 읽기가 힘들어"

레이아웃이 마음에 든다고 했으므로 **구조를 바꾸지 않고 자리만 넓히는** 것이 요구다.
1800x1129 창에서 세로 예산을 재 보면 편집기 몫은 약 500px, 23줄이다:

| 가져가는 것 | 높이 |
|---|---|
| 제목 + 부제 + 실행 | 90 |
| 브라우저 바 | 230 |
| 파일 경로 줄 | 44 |
| 출력 | 150 |
| 남은 것 = 편집기 | ~500 |

고친 것 셋. 순서가 중요하다 — **첫째가 없으면 나머지 둘이 아무것도 안 준다.**

1. **화면이 뷰포트에 맞는다.** 전까지 화면은 `min-h-full` 로 내용만큼 길어지고 편집기
   그리드는 `min-h-[60vh]` 로 고정이었다. 그 상태에서 위의 패널을 접으면 페이지가 짧아질
   뿐 편집기는 한 줄도 안 늘어난다. 지금은 `h-full` + `flex-col` 이고 편집기가 `flex-1` 로
   남은 높이를 전부 가진다.
2. **브라우저 바가 접힌다** (`AC-studio.browser-36`). 이 화면에서 되찾을 수 있는 자리 중
   제일 크다(230px). 접혀도 상태 배지·켜기/끄기 줄과 오류는 남는다 — 안 쓰는 동안에도
   눈에 둬야 하는 것들이다.
3. **넓게 보기** (`AC-web.code.editor-05`). 파일 트리와 그리드 위 패널을 접어 편집기가
   화면을 다 쓴다. `Esc` 로 나온다. 출력 패널은 **안 접는다** — 접으면 넓게 본 채로 누른
   `실행` 이 보고할 데가 없다.

**확인 — 빌드된 앱, mock 드라이버, 1800x1129, 격리 userData:**

| 상태 | 편집기에 보이는 줄 |
|---|---|
| 전 (제보 시점 스크린샷) | 23 |
| 후 · 기본 | 24 |
| 후 · 브라우저 바 접음 | **30줄 전부 + 여백** (파일 트리·출력 그대로) |
| 후 · 넓게 보기 | 30줄 전부, 폭 +256px |

기본 상태의 이득이 1줄뿐인 것은 예산표 그대로다 — 브라우저 바가 펴져 있는 한 자리는
거기 있다. 그래서 접기가 이번 요구의 실제 답이고, ①은 그것이 편집기로 흘러가게 하는
조건이다.

## 2. "`.md` 화면 전용 뷰를 볼 수 있는 토글 버튼"

**제보** — `.harness/feedback/20260814-173031-studio-browser`. 표시 두 개가 한 요청:
GUIDE.md 의 표가 `|---|---|` 로 보이는 자리, 그리고 편집기 오른쪽 위(버튼 자리).

작업대는 스크립트 옆에 `GUIDE.md` 를 싣는데(`AC-studio.browser-32`), 그 파일은 목록의 다른
것과 같은 편집기에서 열린다. **읽으라고 놓아둔 유일한 파일이 원문으로 도착한다.**

`.md` 를 열면 원문/미리보기 토글이 뜬다(다른 확장자에는 안 뜬다). 표를 그려야 해서
GFM(= GitHub 식 마크다운 확장)을 켠다 — 가이드의 절반이 표다. 미리보기는 읽기 전용이고,
링크는 `target="_blank"` 로 나가 메인의 `setWindowOpenHandler` 가 시스템 브라우저로
넘긴다(렌더러가 그 자리에서 이동하면 앱 화면이 통째로 바뀐다).

`react-markdown` + `remark-gfm` 을 새로 넣었다. 직접 만들지 않은 이유: 이 파일이 표·굵게·
코드·링크·목록을 전부 쓴다. 타이포그래피 플러그인은 안 쓴다 — 요소마다 이 앱의 디자인
토큰으로 직접 입혀 두 테마를 그대로 받는다.

**확인** — GUIDE.md 를 열어 토글, 두 테마 모두 캡처. 제목·표(테두리·머리행)·인라인 코드·
외부 링크가 문서로 그려진다. 렌더러 콘솔 에러 0.

## 3. "입력필드라는 걸 알 수 있게 테두리 효과를 추가"

**제보** — `.harness/feedback/20260814-173148-studio-browser`. 표시한 자리는 **탭 목록의 첫
줄**이었다.

여기는 2026-08-12 피드백("입력창인 게 티 났으면")이 이미 한 번 지나간 자리다. 그때 고친
방향은 *탭에서 필드 느낌을 뺀 것*이었고(주소창엔 지구본, 탭은 우물 대신 눌린 표면 + 점),
그래서 요구가 그 결정을 뒤집는 것인지 확인이 필요했다. **유저 확인: 탭 목록의 각 줄.**

두 결정은 부딪히지 않는다. 앞의 것이 고친 혼동은 "둘 중 어디에 타이핑하나"였고, 남아 있던
두 번째 혼동은 "이 줄들이 눌리는 것이긴 한가"였다. 지금 탭은 테두리를 두르되 **우물**
(`bg-muted` + 안쪽 그림자)은 안 쓴다 — 이 디자인 시스템에서 "여기 타이핑한다"를 말하는
것은 우물이지 테두리가 아니다(`components/ui/input.tsx`). `AC-studio.browser-38`.

**확인** — 브라우저를 켜 탭 두 개(활성/비활성)를 만든 상태로 다크에서 캡처. 두 줄 다
테두리를 두르고, 활성만 채워진 표면 + 초록 점을 단다. 주소창은 그대로 우물이다.

### UI 게이트가 두 건을 막았고, 그건 도구 쪽이었다

첫 실행에서 `narrow` 폭 두 테마에 차단이 떴다: `hit-target textbox (429x1 < 24)` 와
`overlap input + textbox`. 원인은 **Monaco 의 입력 대리자**다. 글자를 자기가 그리는
편집기는 키 입력을 받으려고 캐럿 자리에 1px 짜리 숨은 노드를 세워 둔다 — 예전에는
`textarea.inputarea`, EditContext 를 쓰는 지금 경로에서는
`div.native-edit-context[role=textbox]`.

이번 변경이 그것을 **없던 데서 만든 게 아니라, 접힌 선 위로 끌어올렸다.** 전에는 페이지가
스크롤돼서 그 노드가 화면 밖에 있었고 어댑터가 버렸다. 되돌려 확인했다:

| 레이아웃 | narrow/light 판정 |
|---|---|
| 옛 레이아웃(`min-h-full` + `60vh`) | 차단 0 |
| 새 레이아웃(`h-full` + `flex-1`) | 차단 2 |

**어댑터를 고쳤다** — 편집기 안에서 자기가 입력칸이라고 말하는 노드는 추출에서 뺀다.
판정기(`surface-checks.mjs`)는 손대지 않았다: DOM 어휘를 아는 것은 어댑터의 몫이라는
계약 그대로다. 기준선(`surface-baseline.json`)에는 아무것도 추가하지 않았다.

빼는 근거 둘: ⑴ 사람이 겨누는 것은 편집기 표면이지 그 대리자가 아니다. ⑵ 이 노드가
잡히느냐가 **페이지가 스크롤되느냐**에 달려 있어, 안 빼면 같은 화면의 같은 판정이
레이아웃을 조금 고칠 때마다 켜졌다 꺼졌다 한다.

## 남는 것

- **e2e 가 이 셋을 안 덮는다.** 전부 UI 컴포넌트 테스트(happy-dom, Monaco 스텁)와 실제 앱
  수동 확인으로만 덮인다. `smoke.spec.ts` 는 화면이 뜨는 것까지만 본다.
- **넓게 보기·미리보기 상태가 화면을 떠나면 사라진다.** 워크스페이스에 저장하지 않는다.
  가이드를 자주 읽는 사람에겐 매번 두 번 누르는 일이 된다.
- **미리보기는 읽기 전용이다.** 문서를 보면서 고칠 수 없고, 나란히 보는 모드도 없다.
- `react-markdown` 이 렌더러 번들을 1466KB → 1468KB 로 늘렸다(gzip 전). 의존성 93개가
  같이 들어왔다 — unified/remark 생태계다.
- 브라우저 바 접기는 **작업대에만** 있다. 웹·모바일 스크립트 화면에는 그리드 위 패널이
  없어서 접을 것도 없다.
- 탭 테두리는 **다크에서만** 캡처로 확인했다. 라이트는 `surface-verify` 의 96 캡처가
  대비·겹침으로 덮지만, 눈으로 본 것은 다크뿐이다.
