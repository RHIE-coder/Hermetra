### 정한 이름 (유저 확인 2건)

영문은 **단계 명사**로 갔다. 유저 초안의 `Ingestions` · `Processings` · `Storages` 는 셋 다
불가산 명사라 복수형이 오타로 읽힌다. 한국어는 `수집 / 처리 / 저장` 이 이어지는 쪽.

    Jobs 작업 · Sources 소스 · Ingestion 수집 · Processing 처리 · Storage 저장소 · Insights 인사이트

작업(Jobs)은 한 화면으로 뒀다 — 실행 플로우 즐겨찾기와 실행 모니터링을 함께. 정의(Flows)와
실행(Runs)으로 쪼개는 안은 IPC 계약이 생길 때 다시 본다. 근거는
`docs/spec/pipeline/README.md`.

### 판단이 필요했던 자리 — 레일이 넘쳤다

항목이 9개에서 15개가 되며 **1024x720 에서 레일이 31px 모자랐다.** 마지막 행이 7px 조각으로
잘리고 UI 게이트가 차단(30건). 두 단계로 처리했다.

1. **첫 실행 기본값**(유저 선택): 데이터 파이프라인은 열고 레거시는 접는다. 이름이 이미
   순서를 말한다. 차단 30 → 18. **다만 이것으로 끝나지 않았다** — 어댑터가 레거시 화면 9개를
   찍으려면 그 서랍을 열어야 하고, 열면 다시 넘친다. 기본값은 문제를 미룰 뿐이었다.
2. **판정기 모델 수정**(유저 선택): 스크롤로 닿을 수 있어 일부만 보이는 요소는 "작은 표적"이
   아니라 "화면 밖 내용"이다. 어댑터가 `offscreen` 플래그를 내보내고(스크롤되는 축으로 잘린
   경우에만), 판정기는 그 플래그만 읽어 표적 크기 판정을 건너뛴다. DOM 어휘는 어댑터에
   남았다 — 판정기가 재사용 가능해야 한다는 계약(`CLAUDE.md` §7) 그대로다.

   스크롤되지 **않는** 조상이 자른 잘림은 여전히 걸린다. 기준선의 관찰 12건(편집기의 20px
   textarea)도 그대로 검출된다 — 이 변경이 진짜 발견을 덮지 않았다는 증거다.
   기준선 파일은 건드리지 않았다.

레일이 세로로 스크롤되는 것은 이제 정본에 적힌 정상 상태다(`AC-app.shell.sidebar-07`).
