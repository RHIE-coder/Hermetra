# 커버리지 구멍

정의는 있지만 **아직 검증되지 않는** 것들. 각 항목은 전제를 함께 적는다 —
gate 단계가 그 전제가 아직 유효한지 되본다. 전제가 사라졌으면(예: 도구가 생겼으면)
구멍을 메우거나 이 문서를 고친다.

집계 기준: 2026-07-28 handover. 정의된 케이스 **166개** 중 구현 **128개**, 미구현 **38개**.
(케이스는 검증 항목 단위이고, 자동화 테스트 223개와 1:1 대응은 아니다 — 한 케이스를 여러
테스트가 덮기도 하고, 도구 검사 1건이 한 케이스이기도 하다.)

## `gap-web-remote` — 브라우저 화면에 컴포넌트 테스트가 없다

- 대상: CASE-web-001 ~ 012 (12개)
- 전제: 없음. **의도된 구멍이 아니다** — 이 화면이 하네스 도입 전에 만들어졌고 그때는
  UI 테스트 규율이 없었다.
- 영향: 원격 브라우저 화면은 이 제품에서 가장 자주 쓰는 화면인데, 설치 안 됨 → 시작 비활성
  같은 조건부 비활성 로직이 회귀를 막아 주는 것 없이 서 있다.
- 메우는 방법: `RemoteBrowserPage.test.tsx` 를 만들어 store 를 흉내낸다. 다른 페이지
  테스트(`DevicesPage.test.tsx`)가 그 패턴의 본이다.

## `gap-variables-ui` — 변수 화면에 컴포넌트 테스트가 없다

- 대상: CASE-bridge-064 ~ 067 (4개)
- 전제: 없음. 위와 같은 이유.
- 영향: 개인 변수 값이 가려지는지, 복사가 실제로 클립보드로 가는지 아무것도 지키지 않는다.
  개인 값 노출은 조용히 새는 종류의 사고다.
- 메우는 방법: 클립보드는 `navigator.clipboard` 를 흉내내 검증한다.

## `gap-workspace-service` — 워크스페이스 도메인에 테스트가 없다

- 대상: CASE-workspace-005 ~ 015 (11개)
- 전제: 없음. `workspaceManager` 가 Electron `app` 을 직접 부르기 때문에 테스트에서
  띄우기가 번거로웠고, 그대로 미뤄졌다.
- 영향: **마지막 워크스페이스 삭제 금지**·활성 되돌리기·깨진 목록 파일 복구 같은 규칙이
  전부 무방비다. 이 규칙이 깨지면 앱이 상태 없는 화면으로 떨어진다.
- 메우는 방법: `app.getPath` 를 주입 가능하게 바꾸거나 흉내낸다. `connections.ts` ·
  `myDevices.ts` 가 이미 `baseDir` 주입 방식으로 그 문제를 풀어 놨다 — 같은 모양으로
  맞추면 된다.

## `gap-ipc-web-bridge-workspace` — 일부 채널에 API 테스트가 없다

- 대상: CASE-web-010·011 · CASE-bridge-050 · CASE-workspace-005 ~ 012
- 전제: 없음. API 테스트가 있는 채널은 하네스 도입 후에 만든 기능(연결 구성 · 내 디바이스 ·
  인스펙터 · 스크립트)뿐이다.
- 영향: 북마크·시나리오·워크스페이스 채널은 저장 부작용이 검증되지 않는다.
- 메우는 방법: `tests/api/connections.test.ts` 를 본으로 임시 디렉터리에 쓰는 방식.

## `gap-golden-path` — 골든 패스 e2e 가 없다

- 대상: CASE-cross-005 · 006 (2개)
- 전제: 없음. e2e 는 지금 스모크(화면 9개 이동)까지다.
- 영향: 이 제품의 존재 이유인 "웹 → 모바일 인계"가 실제 앱에서 도는지 아무도 확인하지
  않는다. 조각은 단위로 덮여 있지만 배선이 끊겨도 단위 테스트는 초록이다.
- 메우는 방법: mock 드라이버로 예시 시나리오를 실행하는 e2e. 도구 설치가 필요 없다 —
  **막는 것은 전제가 아니라 시간뿐이다.** 우선순위가 가장 높은 구멍이다.

## `gap-visual-baseline` — 화면 시각 위반 237건이 기준선에 얹혀 있다

- 대상: 고유 40건(대비 37 · 잘림 1 · 표적 크기 2)이 폼팩터 3 × 테마 2로 237건.
  목록: `.harness/steward/project/surface-baseline.json`
- 전제: 판정기는 이제 있다(`gap-visual-check` 는 해소됐다). 남은 것은 **고칠지 말지가
  디자인 결정**이라는 것 — 액센트 버튼의 흰 글자(2.17:1)·상단 카운터 알약(1.47:1)·
  타이틀바 제목(2.79:1) 같은 항목은 브랜드 색을 건드리는 일이다.
- 영향: 기준선에 있는 동안은 차단되지 않는다. 새로 생기는 위반만 커밋을 막는다.
- 메우는 방법: 한 항목을 고치고 `surface-baseline.json` 에서 그 줄을 지운다.
  **전체를 다시 생성해 새 위반을 덮지 말 것** — 그러면 가드가 무력해진다.
- 우선순위 제안: 대비 1.47:1 짝(카운터 알약·Anti-detection 뱃지)이 가장 낮다.

## `gap-real-driver` — 실물 드라이버 경로는 검증하지 않는다 (의도됨)

- 대상: 실제 Chromium 기동 · 실제 Appium 세션 · 실기기 조작 전부
- 전제: **CI 에 브라우저 바이너리와 실기기가 없다.** mock 을 기본으로 둔 이유와 같다.
- 영향: 드라이버 어댑터 자체의 버그는 사람이 손으로 확인해야 한다.
- 수동 절차: `HERMETRA_DRIVERS=real npm run dev` 로 띄워 (1) 웹 서버 시작 → 탭 열기 →
  스크립트 실행, (2) Appium 연결 → 인스펙터 세션 → 요소 추출을 지난다. 실행하면
  `runs/` 에 수동 회차로 남긴다.
- 이 구멍은 **유지한다**. 전제가 바뀌는 때는 CI 에 기기 팜이 붙는 날이다.

## `gap-connection-to-session` — 연결 구성 → 세션 경로가 없어서 검증할 것도 없다

- 대상: 실물 모드의 세션 시작 전체
- 전제: 기능 자체가 미구현이다(`docs/spec/mobile/README.md` 의
  `connection-to-session-gap`). 없는 기능에 테스트를 붙일 수 없다.
- 영향: mock 모드에서만 인스펙터·모바일 스크립트가 끝까지 돈다.
- 메우는 방법: 그 기능을 어떻게 할지 정해진 다음이다. 결정이 먼저다.
